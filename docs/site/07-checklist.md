# Чек-лист и расчёт итога

Чек-лист — это данные, а не код. Специалист КК меняет критерии, веса и правила в редакторе, сервер хранит каждую версию, итог считается по одной формуле в интерфейсе, в отчёте и в файле результатов.

## Из чего состоит чек-лист

| Поле | Что задаёт |
| --- | --- |
| `version` | Номер версии. Сохранённые версии неизменяемы, сохранение черновика создаёт `version + 1` |
| `rules` | Общие правила чек-листа: как ставить N/A, что считать основанием, как понимать спорные термины. Модель получает их вместе с каждым критерием |
| `sections` | Названия разделов: в карточке разговора критерии и баллы сгруппированы по ним |
| `criteria` | Список критериев |

### Поля критерия

| Поле | Что задаёт |
| --- | --- |
| `id`, `name`, `sec` | Код, название и номер раздела |
| `type` | `bool` (да, нет), `scale` (одна из ступеней), `flag` (грубая ошибка из нескольких подвопросов) |
| `w` | Вес до перераспределения N/A. Сумма весов не обязана быть 100: итог всё равно приводится к 100 |
| `na`, `naCond` | Разрешён ли ответ N/A и при каком условии |
| `text` | Формулировка критерия для модели и для человека |
| `steps`, `stepText` | Ступени шкалы и описание каждой ступени |
| `questions` | Подвопросы флага: код, подпись, при необходимости уточнение |
| `signal` | `resolution` — критерий решения вопроса (метка «без следующего шага» в аналитике), `risk` — грубая ошибка |
| `channel` | `all`, `chat` или `call` |
| `call` | Уточнение для звонка, необязательное |
| `jev` | Исходное определение вопроса в формате Jev, необязательное |

## Типы критериев

- **Да или нет** (`bool`): «да» даёт полный вес, «нет» — ноль.
- **Шкала** (`scale`): модель выбирает одну из ступеней `steps`, доля баллов — ступень, делённая на максимальную ступень. Например, ступень 15 при шкале `20, 15, 10, 5, 0` даёт 0,75 веса.
- **Флаг** (`flag`): каждый вид нарушения — отдельный вопрос к модели. Флаг ставится, если найдено хотя бы одно нарушение. Флаг не даёт баллов и не входит в итог: он поднимает разговор в очереди, попадает в фильтр «Грубые ошибки», в аналитику и в поле `critical_flag` файла результатов.

## N/A и условие неприменимости

N/A ставится, только если он разрешён у критерия (`na: true`) и выполнено его условие `naCond`. Критерий с N/A исключается из расчёта, а его вес распределяется между остальными применимыми критериями пропорционально их весам. Так короткий разговор, где часть действий не требовалась, не наказывается и не получает лишних баллов.

Если ни один критерий с весом не применим к разговору, итог не рассчитывается: на его месте прочерк, а в файле результатов такая запись не пройдёт проверку. Это честнее, чем ноль или сто.

## Каналы и уточнение для звонка

- `channel: "all"` — критерий для чатов и звонков.
- `channel: "chat"` или `"call"` — критерий только для одного канала. Такой критерий обязан разрешать N/A (`na: true`), иначе сохранение версии отклоняется с кодом 422. На диалоге другого канала он получает N/A без обращения к модели, обоснование — «Критерий для другого канала».
- `call` — уточнение формулировки для устной речи. Модель получает его после `text` только на звонке, запрос по чату не меняется. Так один чек-лист служит и чатам, и звонкам без дублирования критериев.

Пример уточнения из начальной версии: для звонка критерий ведения диалога просит не оценивать темп речи и дикцию и не вменять оператору ошибки распознавания речи.

## Формула итога

Итог = 100 × Σ(вес × доля) / Σ(вес применимых критериев)

- Доля: «да» — 1, «нет» — 0, шкала — ступень / максимальная ступень.
- N/A и критерии, которые ещё ждут оценки, исключаются из обеих сумм. Флаги в сумму не входят.
- Округляется только итог: до двух знаков, половина вверх (88,125 даёт 88,13).
- Ответ берётся с учётом последнего решения по апелляции или проверке. Исходный ответ модели не меняется никогда.

### Пример расчёта

Начальная версия чек-листа, чат с двумя неприменимыми критериями:

| Критерий | Вес | Ответ | Доля | Вес × доля |
| --- | --- | --- | --- | --- |
| 01 Установление контакта | 10 | да | 1 | 10 |
| 02 Выявление потребности | 15 | N/A | — | исключён |
| 03 Идентификация | 20 | N/A | — | исключён |
| 04 Корректная и полная консультация | 20 | 15 из 20 | 0,75 | 15 |
| 05 Эмпатия и клиентоориентированность | 15 | да | 1 | 15 |
| 06 Управление диалогом | 15 | 7 из 10 | 0,7 | 10,5 |
| 07 Завершение | 5 | нет | 0 | 0 |
| 08 Грубые ошибки | 0 | флаг | — | не входит |

Сумма весов применимых критериев — 65, набрано 50,5. Итог: 100 × 50,5 / 65 = 77,69.

Если в том же разговоре идентификация требовалась и пройдена («да» по критерию 03), применимых весов становится 85, набрано 70,5, итог — 82,94. Оба значения входят в общие векторы проверки `tests/fixtures/scoring_vectors.json`: один набор векторов проверяется и в Python, и в JavaScript.

### Как карточка показывает расчёт

Блок «Как посчитан итог» в карточке разговора повторяет формулу: сколько баллов набрано из применимых, у каких критериев N/A и что их вес распределён между остальными. Если часть критериев ещё ждёт оценки, карточка пишет «итог предварительный». «Главные потери» — критерии, на которых разговор потерял больше всего баллов из 100.

## Версии чек-листа

Каждое сохранение создаёт новую неизменяемую версию с короткой пометкой, что изменилось. Если черновик основан на устаревшей версии, сервер отвечает 409 и просит обновить страницу. Сохранение отклоняется с кодом 422, если повторяется код критерия, указан несуществующий раздел, у шкалы нет ступеней или описания ступени, у критерия одного канала не разрешён N/A.

Любую версию можно выгрузить в JSON, CSV для Excel, Markdown и памятку для печати A4, а две версии — сравнить. Как это сделать в интерфейсе, описано в [руководстве специалиста КК](qa-specialist), через API — в [справочнике API](api).

## Что пересчитывается после правки

Готовые ответы привязаны к отпечатку смысла критерия. В отпечаток входят общие правила и поля смысла: `text`, `type`, `steps`, `stepText`, `na`, `naCond`, `questions`, `channel` и `jev`, если он задан. Уточнение `call` входит только в отпечаток звонка. Модель и версия промпта в отпечаток не входят, поэтому смена модели не сбрасывает готовые ответы.

| Что изменили | Что происходит |
| --- | --- |
| Название, вес, раздел, сигнал | Итог пересчитывается сразу, модель не вызывается |
| Текст, тип, ступени, N/A, условие N/A, подвопросы, канал, `jev` | Критерий ждёт новой оценки во всех диалогах |
| Уточнение `call` | Новой оценки ждут только звонки |
| Общие правила | Новой оценки ждёт весь чек-лист |
| Добавлен критерий | Ждёт оценки; итог до неё считается без него и помечен как предварительный |

«Оценить» запускает модель только по критериям без ответа текущего смысла, остальные ответы берутся из сохранённых. Если вернуть прежнюю формулировку, снова подойдут ответы, полученные для неё раньше.

## Апелляции после смены критерия

Ожидающие апелляции по критерию, у которого изменился смысл или который удалён, получают статус `closed`. Решения, принятые по прежнему смыслу, к новому смыслу не применяются: итог считается по новому ответу модели, пока по нему не принято новое решение.
