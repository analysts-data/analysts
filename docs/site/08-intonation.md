# Интонация звонка

Для звонков система разбирает звук записи и считает интонационные признаки: тон, громкость, темп, паузы и перебивания. Расчёт идёт на сервере, запись никуда не отправляется. Результат виден в карточке звонка и в виде короткой сводки попадает в запрос к модели.

## Как считается

1. При первом открытии карточки звонка сервер получает свежую ссылку на запись, скачивает её в память и декодирует через ffmpeg в моно 16 кГц.
2. Praat строит кадры тона (F0) и интенсивности.
3. Запись моно, поэтому говорящие различаются только по расшифровке: границы реплики берутся из её метки времени и длины текста, речь реплики — громкие кадры в этом окне.
4. Для каждого говорящего вычисляется обычная манера, затем каждая реплика сравнивается с ней.
5. Результат сохраняется в базе, повторное открытие карточки запись не скачивает.

## Что измеряется по реплике

| Показатель | Смысл |
| --- | --- |
| `f0` | Медиана тона, Гц |
| `range_st` | Размах тона между 10-м и 90-м процентилями, полутоны |
| `db` | Средняя интенсивность речи, дБ по шкале записи (не абсолютная громкость) |
| `wps` | Слов в секунду; длительность берётся из звука, а не из текста |
| `pause` | Тишина перед репликой после предыдущей реплики клиента или оператора, с |

Значение `null` означает, что речи, тона или предыдущей реплики нет. Для тона нужно не меньше 10 кадров с голосом.

## Обычная манера говорящего

Для клиента и оператора отдельно берутся медианы `f0`, `db` и `wps` по их репликам основной части разговора. Участок до подключения оператора, удержание, разговор с коллегой и участок после завершения в манеру не входят и отметок не получают. Относительные отметки ставятся, только если у говорящего не меньше 3 реплик, а сама реплика звучит не меньше 1,5 секунды: короткие «Алло?» и «Да-да» не показательны.

## Отметки и пороги

| Отметка | В карточке | Условие |
| --- | --- | --- |
| `raised` | ↑ тон | Тон на 3 полутона выше обычного для говорящего или на 6 дБ громче |
| `fast` | быстро | Темп не меньше 1,5 обычного для говорящего и не меньше 3,5 слова в секунду |
| `monotone` | монотонно | Размах тона меньше 2 полутонов на реплике от 4 секунд |
| `long_pause` | пауза N с | Ответ оператора клиенту после 5 секунд тишины и больше |
| `overlap` | перебивание | Реплика началась на 1 секунду и больше раньше конца чужой реплики и позже её начала |

`raised` и `fast` считаются относительно манеры того же говорящего, остальные отметки — абсолютные. Короткая вставка внутри длинной чужой реплики перебиванием не считается.

## Что видит пользователь

- Панель «Интонация» в карточке звонка: сводка по-русски, например «Клиент повысил тон в репликах 12–14» или «Пауза 9 с перед ответом оператора (реплика 20)». Подряд идущие реплики одного говорящего объединяются в диапазон.
- Значки у реплик расшифровки: «↑ тон», «монотонно», «быстро», «пауза N с», «перебивание».
- Если отклонений нет: «Тон, громкость и темп в обычной манере говорящих, долгих пауз перед ответом нет».
- Пока запись разбирается: «Интонация: разбираем запись…». Если запись получить не удалось: «Интонация недоступна: запись не загрузилась». У чата и звонка без записи панели нет.

## Интонация в оценке звонка

После текста звонка модель получает блок «Анализ звука записи» со строками сводки и правилом: о тоне, паузах и темпе судить только по этим строкам, ничего сверх них о звуке не утверждать, дикцию и разборчивость по ним не оценивать. В блоке только роли и номера реплик, без текста и имён. Так модель может учесть, например, долгую паузу без предупреждения при оценке ведения разговора.

- Отметки интонации не входят в формулу итога: итог по-прежнему считается только из ответов по критериям.
- Если записи нет, ffmpeg не установлен или разбор не удался, блока нет, а запрос к модели остаётся прежним. Оценка звонка при этом не прерывается.
- Появление интонации не пересчитывает готовые ответы: она учитывается в следующих оценках звонка.
- Запрет отправки реальных звонков проверяется до разбора звука (раздел [Безопасность и данные](security)).

## Ограничения

- Пороги эвристические: подобраны по литературе о просодии и нескольким звонкам DEV, не обучены. Их стоит откалибровать на звонках с разметкой специалистов КК.
- Запись моно: участки, где говорят оба, разделяются только по меткам расшифровки, точность зависит от распознавания речи.
- Громкость измеряется по шкале конкретной записи, поэтому сравнивается только с тем же говорящим в том же звонке.
- Система измеряет только интонационные признаки и не распознаёт эмоции оператора или клиента: отметка «↑ тон» говорит о звуке, а не о состоянии человека. Это сделано намеренно: Регламент ЕС об ИИ (AI Act) запрещает распознавание эмоций на рабочем месте, а у брокера есть бизнес в ЕС.
- Нужен системный `ffmpeg` в `PATH`. Без него панель показывает «Интонация недоступна», остальная система работает.

## Через API

`GET /api/dialogs/{id}/prosody` возвращает разбор звонка:

```json
{
  "lines": [{"n": 12, "f0": 214, "range_st": 6.3, "db": 71.2, "wps": 2.6, "pause": 0.8, "flags": ["raised"]}],
  "speakers": {"client": {"f0": 180.0, "db": 66.0, "wps": 2.5, "lines": 30},
               "operator": {"f0": 110.0, "db": 65.0, "wps": 2.3, "lines": 28}},
  "summary": ["Клиент повысил тон в репликах 12–14", "Пауза 9 с перед ответом оператора (реплика 20)"]
}
```

Код 404 — чат, неизвестный диалог или звонок без записи; 502 — запись не получена. Ответ 502 не сохраняется, следующий запрос пробует снова.
