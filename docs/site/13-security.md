# Безопасность и данные

Раздел для службы безопасности и ИТ брокера: какие данные куда уходят, что хранится на сервере и какие ограничения действуют по умолчанию.

## Куда уходят данные

| Данные | Где обрабатываются |
| --- | --- |
| Текст диалога | Обезличивается на сервере, затем уходит выбранной модели: провайдеру в Казахстане, локальной модели или внешнему API |
| Запись звонка | Скачивается в память сервера и разбирается локально (ffmpeg и Praat). Наружу не отправляется |
| Сводка интонации | Уходит модели вместе с текстом звонка: только роли и номера реплик, без текста и имён |
| Ключи моделей | Хранятся на сервере, наружу уходят только в запросах к своему провайдеру |
| Ответы, решения, версии чек-листа | База SQLite на сервере (`CQA_DB_PATH`) |

В режиме записанных ответов (`CQA_LLM_MODE=replay`, например `make demo`) модель не вызывается и текст никуда не уходит.

## Интонация без распознавания эмоций

Из записи звонка считаются только интонационные признаки — тон, громкость, темп, паузы и перебивания — относительно обычной манеры того же говорящего. Эмоции оператора и клиента система не распознаёт и не выводит: Регламент ЕС об ИИ (AI Act) запрещает распознавание эмоций на рабочем месте, а у брокера есть бизнес в ЕС. Подробно — [Интонация звонка](intonation).

## Плашка режима

Шапка интерфейса всегда показывает, где обрабатываются данные: «Обработка: Казахстан», «локально» или «внешний провайдер», включено ли обезличивание, какая модель отвечает и есть ли второе мнение. Плашку нельзя скрыть. Она выделяется, если данные уходят внешнему провайдеру или обезличивание выключено при нелокальной модели. Сменить режим кликом по плашке может только роль «Специалист КК». Место обработки задаёт провайдер основной модели (`where`) или `CQA_DATA_WHERE`.

## Обезличивание

Обезличивание включено по умолчанию (`CQA_ANONYMIZE`) и выполняется на сервере до отправки диалога любой модели: основной, второму мнению и Jev. Шаблоны применяются по порядку: почта, IBAN Казахстана, номер карты, ИИН, телефон, затем имена (правила — `src/cqa/domain/anonymize.py`). В базе и в интерфейсе остаётся исходный текст, меняется только то, что уходит модели.

| Что ищется | Чем заменяется |
| --- | --- |
| Адрес электронной почты: `имя@домен.зона` | `[ПОЧТА]` |
| IBAN Казахстана: `KZ`, 2 цифры и 16 заглавных латинских букв или цифр | `[НОМЕР_СЧЁТА]` |
| Номер карты: 16 цифр группами по 4 через пробел или дефис; 13–19 цифр слитно — только если проходят проверку Луна (номер заявки без Луна остаётся) | `[НОМЕР_КАРТЫ]` |
| ИИН: 12 цифр слитно или с пробелами 6 + 6 и 4 + 4 + 4 | `[ДАННЫЕ_ИДЕНТИФИКАЦИИ]` |
| Телефон: `+7` или `8` и ещё 10 цифр, между ними допускаются пробелы, скобки и дефисы; номер вида `7 777 123 45 67` — только после слов «телефон», «номер», «тел», «звоните» в пределах 20 символов | `[ТЕЛЕФОН]` |
| Имя оператора | `[ИМЯ_ОПЕРАТОРА]` |
| Имена клиентов | `[ИМЯ_КЛИЕНТА_1]`, `[ИМЯ_КЛИЕНТА_2]`, … |

- Имена находятся по подсказкам на русском, казахском и английском («меня зовут», «менің атым», «my name is»), по представлению («я …», «I'm …») и по короткому ответу клиента на вопрос оператора об имени. Найденное имя заменяется во всём диалоге без учёта регистра вместе с близкими вариантами написания, которые даёт распознавание речи (сходство не ниже 0,8, слова от 4 букв).
- Маски организаторов в квадратных скобках не меняются.
- Номера реплик, роли и время сохраняются, поэтому ссылки на реплики-основания остаются точными.
- Обезличивание основано на шаблонах и подсказках, а не на распознавании именованных сущностей: необычное представление может быть пропущено.

Выключить обезличивание можно в окне режима. Если транскрипты при этом уйдут во внешний API, интерфейс просит подтверждение: «Транскрипты уйдут во внешний API без обезличивания».

## Запрет отправки реальных звонков

Звонки — записи реальных разговоров. В режиме живой модели (`CQA_LLM_MODE=live`) звонок уходит модели только при разрешении человека: `CQA_ALLOW_REAL_DATA=1` в `.env` или флажок «Разрешить отправлять модели реальные звонки» в окне режима с подтверждением «Реальные звонки будут отправляться модели». Без разрешения оценка звонка завершается ошибкой с подсказкой, модель не вызывается. Проверка выполняется до разбора звука и до обезличивания, ей подчиняются интерфейс, `make results ARGS=--evaluate` и `make eval`.

Проверка связи с провайдером (`POST /api/providers/{id}/check`) отправляет только синтетическую фразу «Ответь одним словом: да».

## Ключи только на запись

- Ключи моделей, Jev и OpenRouter задаются в `.env` или в окне режима и хранятся на сервере.
- API никогда не возвращает ключ: в ответах есть только признаки `has_llm_key`, `has_jev_key` и `has_key` у провайдера.
- Пустое поле ключа при изменении оставляет сохранённый ключ.
- В журнал сервера ключи не пишутся.

## Ссылки организаторов

- Адрес API организаторов задаётся в `CQA_ORG_API_URL` или полем в интерфейсе. Сервер хранит его у себя и не возвращает ни в одном ответе: браузер адреса не видит.
- Ссылки на записи звонков подписаны и живут около часа. Сервер хранит исходную ссылку в базе и не отдаёт её в ответах. Плеер обращается к `/api/dialogs/{id}/audio`, и сервер каждый раз перенаправляет его на свежую ссылку с запретом кэширования. Подписанные адреса не пишутся в журнал.

## Доступ к серверу

- Входа и учётных записей нет: роль («Специалист КК», «Оператор», «Проверяющий») переключается кнопкой в шапке и не является механизмом доступа.
- `make run` и `make demo` слушают только `127.0.0.1` и входа не требуют.
- Для показа по сети `make share` слушает `0.0.0.0` и включает общий токен доступа (`CQA_ACCESS_TOKEN`; пустой — токен создаётся на запуск). Вход по ссылке `/login?token=<токен>` ставит cookie `cqa_access` (HttpOnly, SameSite=Lax). Без неё страницы показывают «Доступ по ссылке с токеном», `/api/*` отвечает 401, открыт только `/api/health`. Токен сравнивается за постоянное время, в журнале сервера значение `token=` заменяется на `***`.
- Отозвать доступ — перезапустить сервер с новым токеном или без сети (`make run`).
- Токен общий, учётных записей нет: в продуктивной установке ограничивайте доступ ещё и сетевыми средствами — VPN, обратный прокси с аутентификацией, список разрешённых адресов.
- Кросс-доменные запросы браузера разрешены только с доменов `*.dynamics.com`, без cookies (см. [Встраивание в Dynamics 365](dynamics)).


## Что не попадает в репозиторий

`.env`, каталог `data/` (база, снимки наборов), записи звонков, ключи и адрес API организаторов в git не хранятся. Проверка `make check` ищет сигнатуры секретов в отслеживаемых файлах и останавливает сборку при находке. В `.env.example` — только имена переменных.
