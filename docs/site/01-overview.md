# Обзор продукта

CQA оценивает чаты и звонки контакт-центра по чек-листу. Языковая модель отвечает на каждый критерий с обоснованием и репликой-основанием, итог считается по формуле чек-листа, спорные ответы уходят человеку на проверку, оператор может оспорить оценку. Для звонков интонация (тон, громкость, темп, паузы, перебивания) считается локально из записи.

Сервис работает одним процессом: сервер FastAPI и база SQLite, интерфейс открывается в браузере на том же адресе. Документация, которую вы читаете, отдаётся тем же сервером по адресу `/docs/` и работает без доступа в интернет.

## Для кого

| Роль | Что делает в CQA | Раздел |
| --- | --- | --- |
| Специалист контроля качества | Загружает наборы, запускает оценку, разбирает очередь, правит чек-лист, ставит ручные ответы | [Руководство специалиста КК](qa-specialist) |
| Оператор | Смотрит оценки и основания, подаёт апелляции, учится на примерах | [Руководство оператора](operator) |
| Проверяющий | Решает апелляции, просматривает грубые ошибки | [Руководство проверяющего](reviewer) |
| Руководитель | Смотрит аналитику и отчёт для руководства | [Руководителю](manager) |
| ИТ брокера, интегратор | Встраивает CQA в свои системы по HTTP API и в Dynamics 365 | [Интеграция по API](integration), [Справочник API](api), [Встраивание в Dynamics 365](dynamics) |
| Жюри | Проверяет, как устроены оценка, правила и защита данных | [Правила, пороги и их обоснование](rules), [Безопасность и данные](security) |

Учётных записей нет: роль переключается кнопкой в шапке интерфейса. При показе по сети вход — по ссылке с общим токеном.

## Что происходит с диалогом

1. **Загрузка.** Набор приходит из API источника по `group_id`, файлом JSON в том же формате или вставкой текста диалога. Повторы по `id` пропускаются.
2. **Подготовка.** Реплики размечаются по ролям (клиент, оператор, бот, система). У звонка удержание и разговор с коллегой сворачиваются и не оцениваются. Перед отправкой модели имена, телефоны и другие персональные данные обезличиваются.
3. **Оценка.** Модель получает чек-лист и диалог и отвечает по каждому критерию отдельным запросом: ответ, обоснование, номера реплик-оснований, короткая причина снижения и пример лучшей реплики. Цитату-основание сервер сверяет с текстом диалога дословно.
4. **Итог.** Итог считается по формуле чек-листа: N/A исключается, его вес перераспределяется на применимые критерии. Грубые ошибки в сумму не входят, они отмечают диалог отдельно. Подробно — [Чек-лист и расчёт итога](checklist).
5. **Проверка человеком.** Расхождение двух моделей, непрошедшая цитата, неуверенный ответ Jev попадают в очередь «Нужна проверка». Решение человека записывается с автором и причиной, исходный ответ модели не перезаписывается.
6. **Апелляции и аналитика.** Оператор оспаривает оценку критерия или грубую ошибку, проверяющий решает. Аналитика и отчёт для руководства учитывают последнее решение.

## Каналы: чат и звонок

- **Чат** оценивается по тексту реплик.
- **Звонок** оценивается по расшифровке. У каждой реплики есть секунда начала в записи, поэтому из карточки можно прослушать нужное место. Интонация считается из записи локально и попадает в запрос модели короткой сводкой; на итог она напрямую не влияет. Подробно — [Интонация звонка](intonation).
- Критерий в чек-листе может относиться к обоим каналам или только к одному. У критерия может быть уточнение для звонка: модель получает его только на звонке, запрос по чату не меняется.

## Режимы оценки

Режим переключается в интерфейсе кликом по плашке режима в шапке (роль «Специалист КК») и применяется без перезапуска. Начальные значения задаются в `.env`.

| Режим | Что это | Когда выбирать |
| --- | --- | --- |
| Модель у провайдера в Казахстане | По умолчанию: `qwen3-6` у провайдера alem, данные обезличиваются до отправки, плашка «Обработка: Казахстан» | Основной режим |
| Другие провайдеры OpenAI-формата | Любое число провайдеров со своими ключами: адрес, модель, профиль, место обработки | Запасной провайдер, сравнение моделей |
| Второе мнение | Те же вопросы по критериям уходят второй модели (Jev или другой провайдер), расхождения идут на проверку; грубая ошибка засчитывается, если её нашла любая из моделей | Важные наборы, контроль качества модели |
| «Только Jev» | Все критерии диалога отвечает Jev одним запросом, с вероятностью ответа и без обоснований; ответ с вероятностью ниже 0,6 уходит на проверку | Быстрая и дешёвая первичная сортировка |
| Jev Router через OpenRouter | Встроенный провайдер `openrouter-jev`: чат-модель OpenAI-формата, отвечает с обоснованием и цитатой, как любая языковая модель | Основная модель или второе мнение, нужен ключ OpenRouter |
| Локальная модель | Любой OpenAI-совместимый сервер на своей машине (Ollama, vLLM, LM Studio), плашка «Обработка: локально» | Данные не должны покидать контур |

Без ключа и без сети сервис работает на записанных ответах модели (`CQA_LLM_MODE=replay`): так устроены `make demo` и автотесты. См. [Быстрый старт](quickstart).

## Защита данных

- **Обезличивание** включено по умолчанию: персональные данные заменяются метками до отправки во внешнюю модель.
- **Реальные звонки** в живом режиме уходят в модель только при `CQA_ALLOW_REAL_DATA=1`. Этот флаг ставит человек; без него оценка звонка останавливается с понятной ошибкой.
- **Запись звонка** разбирается на сервере (ffmpeg и Praat) и никуда не отправляется.
- **Ключи** только записываются: ни в ответах API, ни в журнале их нет.
- **Плашка режима** в шапке всегда показывает, где обрабатываются данные: в Казахстане, локально или во внешнем API.

Подробно — [Безопасность и данные](security).

## Качество и стоимость

- На эталоне из 24 чатов DEV, размеченных командой, согласие с разметкой 0,96 (RU 0,94, KZ 0,95, EN 1,00); полнота грубых ошибок 1,00 без ложных срабатываний.
- Одна оценка чата — 10 вызовов основной модели: 7 критериев и 3 подвопроса грубой ошибки; второе мнение Jev добавляет 1 запрос. «Только Jev» — 1 запрос на диалог.
- В прогоне эталона 24 диалога оценены за 3 мин 43 с, около 9 секунд на диалог.
- В карточке диалога видно число вызовов, время и цену последней оценки.

## Ограничения

- Нет учётных записей: роль — переключатель в интерфейсе. Для показа по сети есть общий токен доступа (`make share`).
- Интонация на итог не влияет напрямую: модель оценивает текст звонка и видит только сводку по звуку.
- Трендов по неделям нет: в данных источника нет дат чатов.
- Скоро: оценки по сотрудникам, сравнение запусков.
