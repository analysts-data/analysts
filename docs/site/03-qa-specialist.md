# Руководство специалиста КК

Специалист контроля качества загружает диалоги, запускает оценку моделью, проверяет спорные ответы, ставит ручные оценки и ведёт чек-лист. Все действия этого раздела доступны в роли «Специалист КК»: переключатель ролей находится в шапке справа. В ролях «Оператор» и «Проверяющий» кнопки загрузки, оценки и редактирования скрыты.

## Экран «Диалоги»

Экран открывается по адресу `#/queue` и по умолчанию. Сверху — способы загрузки, панель оценки набора и плитки-фильтры, ниже — таблица диалогов.

### Загрузка диалогов

| Действие | Что происходит |
| --- | --- |
| «Получить набор» | Сервер загружает набор по `group_id` из поля слева (по умолчанию `DEV`). Если заполнено поле «Ссылка API организаторов», сервер сохраняет ссылку у себя и затем сам забирает этот набор раз в 5 минут; под заголовком появляется строка «Автосинхронизация … раз в 5 минут». |
| «Загрузить JSON» | Файл в формате ответа API организаторов загружается как есть. |
| «Вставить диалог» | Окно с полями «Название», «Канал» (чат или звонок) и «Текст диалога». |

Повторные диалоги с тем же идентификатором пропускаются. Оценка после загрузки сама не запускается.

### Вставка диалога текстом

1. Нажмите «Вставить диалог».
2. Введите название и выберите канал.
3. Вставьте текст: каждая реплика — строка вида `Клиент: …`, `Оператор: …`, `Бот: …` или `Система: …`. Строка без роли продолжает предыдущую реплику.
4. Нажмите «Сохранить». Карточка нового диалога откроется сразу.
5. В окне «Диалог добавлен» выберите «Оценить» или «Позже».

Диалог без реплики оператора не сохраняется: сервер вернёт ошибку, текст останется в окне.

### Очередь и фильтры

Диалоги идут группами:

1. «Грубые ошибки» — флаг нарушения, диалог ещё не отмечен проверенным.
2. «Нужна проверка человека» — модели разошлись или цитата не нашлась в реплике (в режиме «Только Jev» — Jev не уверен в ответе).
3. «Без понятного следующего шага» — критерий с сигналом «Решение запроса» ниже верхней ступени.
4. «Остальные».

Внутри группы диалоги отсортированы по итогу по возрастанию. Колонка «Почему в очереди» называет причину, «Где потеряны баллы» — до трёх критериев с потерями, «Статус» — «Ждёт оценки», «Апелляция», «Проверен» или «Не проверен».

Плитки «Грубые ошибки», «Нужна проверка» и «Без следующего шага» включают фильтр по группе, повторное нажатие снимает его. Плитка «Апелляции» открывает экран апелляций, «Средний итог» — аналитику. Над таблицей есть поиск по номеру диалога и тексту реплик, списки «Язык» и «Канал» и кнопка «Сбросить фильтры». Фильтры хранятся в адресе, например `#/queue?grp=risk&lang=KZ`, поэтому ссылку на выборку можно переслать коллеге.

Клавиши J и K перемещают выделение по списку, Enter открывает карточку.

## Оценка моделью

Панель «Оценка набора» показывает, сколько диалогов оценено по текущей версии чек-листа, число вызовов и стоимость.

- «Оценить» запускает оценку диалогов, видимых в таблице, в порядке очереди. Без фильтров оценивается весь набор.
- Во время оценки видна строка «Идёт оценка: оценено N из M ответов по критериям», число вызовов, стоимость и оставшееся время. «Остановить» прерывает запуск: диалоги в работе завершаются, новые не начинаются.
- Повторное «Оценить» продолжает с места остановки: готовые ответы не пересчитываются.
- Прогресс сохраняется после перезагрузки страницы: идущий запуск запоминается в браузере.
- Ошибки запуска выводятся рядом с прогрессом, список по диалогам раскрывается по «Показать ошибки».

Модель оценивает только критерии без ответа. Ручные ответы она не меняет.

## Карточка разговора

Карточка открывается по адресу `#/d/<id>`. Ссылки «Предыдущий» и «Следующий» и клавиши J и K переходят по очереди.

### Сводка

- «Итог» — число из 100 и баллы по секциям. Раздел «Как посчитан итог» показывает набранные баллы из применимых, критерии с N/A и перераспределение их веса. Если часть критериев ждёт оценки, итог помечен как предварительный. Формула — в разделе [Чек-лист и расчёт итога](checklist).
- «Почему снижена оценка» — до трёх главных потерь с обоснованием и номером реплики. Нажатие переводит к критерию и подсвечивает реплику.
- «Грубые ошибки» — ответ по каждому виду нарушения. Флаг на итог не влияет.
- Строка «Второе мнение совпало по N из M критериев» появляется, если второе мнение включено.

### Критерии и основания

Справа — критерии по секциям. Раскрытый критерий показывает ответ на шкале, обоснование, реплики-основания с кнопкой «К реплике» и, при потере баллов, блок «Как сказать лучше». Наведение на критерий подсвечивает его реплики в расшифровке, кнопка «Развернуть все обоснования» раскрывает все критерии сразу. Если реплик-оснований нет (действие пропущено), карточка пишет, какой участок проверен.

У звонка над расшифровкой — плеер и панель «Интонация», см. [Интонация звонка](intonation).

### Оценить моделью

Кнопка «Оценить моделью» в шапке карточки появляется, если у диалога есть критерии без ответа. Она запускает оценку только этого диалога.

### Ручной ответ

- У неоценённого критерия — «Оценить вручную».
- У оценённого — «Изменить ответ».

В окне выберите ответ из допустимых для критерия (для флага — отметьте найденные нарушения), при желании добавьте обоснование и нажмите «Сохранить ответ». Ответ получает метку «Поставлено вручную», итог пересчитывается сразу. Повторная оценка моделью ручной ответ не меняет, прежний ответ модели остаётся в базе. Пока по критерию есть апелляция или решение, кнопка «Изменить ответ» не показывается: решение важнее ответа.

### Нужна проверка: решения в карточке

Если второе мнение разошлось с основной моделью, в критерии появляется блок «Второе мнение: …» с кнопками «Оставить …» и «Принять …». Если цитата не нашлась в реплике или Jev не уверен в ответе — кнопки «Оставить …» и «Изменить». В окне решения причина обязательна (не короче 5 символов). Решение сохраняется отдельной записью, исходный ответ модели не меняется, а в критерии появляется «История оценки».

### Отметить проверенным

«Отметить проверенным» убирает диалог из верхних групп очереди. «Снять отметку» возвращает его.

## Чек-лист

Редактор открывается на экране «Чек-лист» (`#/checklist`). Черновик — копия применяемой версии, правки живут в браузере до сохранения.

### Поля критерия

| Поле | Назначение |
| --- | --- |
| Название, Секция | Как критерий виден в карточке и аналитике. |
| Что проверяем | Текст, который модель получает дословно. |
| Уточнение для звонка | Необязательно. Модель получает его только на звонках, запрос по чатам не меняется. |
| Тип ответа | «Да / Нет», «Шкала» или «Флаг нарушения, без баллов». |
| Вес | Доля в итоге до перераспределения N/A. |
| N/A разрешён, Условие N/A | Когда критерий неприменим. |
| Ступени шкалы | По строке на ступень: «балл: что значит». |
| Подвопросы | Для флага: по строке на вид нарушения. |
| Канал | «Все каналы», «Чат» или «Звонок». Для одного канала N/A включается автоматически. |
| Сигнал | «Решение запроса» или «Риск»: на нём строятся метка «Без следующего шага» и плитки аналитики. |

Ниже списка критериев — «Сумма весов», кнопка «Добавить критерий» и список версий. Под редактором — поле «Общие правила»: модель получает их вместе с каждым критерием, поэтому их смена требует новой оценки всего чек-листа.

### Сохранение и версии

1. Внесите правки. Изменённые критерии помечены «изменён».
2. «Что изменится» покажет разницу черновика с текущей версией: что добавлено, изменено или удалено и что потребует новой оценки.
3. «Сохранить как vN» создаёт новую версию. Смена веса пересчитывает итоги без модели. Смена текста, типа, шкалы или N/A требует новой оценки этого критерия, смена уточнения для звонка — только на звонках.
4. Если критерии ждут оценки, появится баннер с кнопкой «Оценить набор».

«Отменить изменения» сбрасывает черновик. Апелляции на рассмотрении по удалённым критериям и по критериям, которые требуют новой оценки, закрываются со статусом «Закрыта». Смена веса апелляции не закрывает.

В списке версий у каждой прежней версии есть «Сравнить с текущей».

### Экспорт и импорт

- Меню «Экспорт ▾»: выберите версию и формат — «JSON», «Excel (CSV)», «Markdown» или «Памятка для печати» (открывается во вкладке, формат A4).
- «Загрузить из файла» кладёт JSON чек-листа в черновик. Кнопка недоступна, пока есть несохранённые правки.
- «Импорт из формата Jev» обновляет черновик по ID критериев, веса настраиваются отдельно. «Экспорт в формат Jev» сохраняет вопросы для редактора Jev.

## Режим оценки

Плашка в шапке показывает, где обрабатываются данные, обезличены ли транскрипты, какая модель отвечает и включено ли второе мнение. Нажатие открывает окно «Режим оценки»:

- «Оценщик»: «Языковая модель» или «Только Jev (быстро, без обоснований)».
- Модели OpenAI-формата: отметьте основную, «Проверить», «Изменить», «Удалить», «Добавить модель».
- «Второе мнение», «Ключ Jev».
- «Обезличивать транскрипты перед отправкой модели» и «Разрешить отправлять модели реальные звонки».

Режим применяется сразу, без перезапуска сервера. Ключи хранятся на сервере и в браузер не возвращаются. Отключение обезличивания для внешнего API и разрешение реальных звонков требуют подтверждения. Подробнее — [Безопасность и данные](security).

## Владельцы причин

На экране «Аналитика» в таблице «Повторяющиеся причины» колонка «Что менять» назначает адресата причины: «Инструкция», «Сервис» или «Продукт». Значение сохраняется на сервере и попадает в отчёт для руководства, см. [Руководителю](manager).
