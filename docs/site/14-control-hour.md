# Контрольный час

На контрольном часе организаторы объявляют `group_id` контрольного набора. Команда загружает набор, оценивает его и публикует файл результатов в формате JSON 1.0 в своём репозитории до срока. Пошаговый регламент с временем и ответственными — [регламент контрольного часа и защиты](runbook).

## Файл результатов одной командой

Файл собирает `make results` из той же базы, что видит интерфейс: ответы модели, ручные ответы и решения по апелляциям.

| Команда | Что делает |
| --- | --- |
| `make results SET=dev` | Файл по снимку DEV (`CQA_EVAL_DATASET`) |
| `make results SET=prod GROUP=<group_id>` | Файл по контрольному набору: ровно `conversation_id` из снимка `data/raw/<group_id>.json`, который сервер сохранил при «Получить набор» |
| `make results SET=prod ARGS="--source <файл>"` | Файл по набору, загруженному файлом |
| `make results SET=prod GROUP=<group_id> ARGS=--evaluate` | Загрузить набор, оценить всё, чего нет, и выгрузить файл |

С `ARGS=--evaluate` набор загружается так же, как кнопками «Получить набор» или «Загрузить JSON», затем модель из `.env` и режима интерфейса оценивает пары без ответа текущего чек-листа. Каждые 5 секунд печатается строка `оценка done/total, ошибок N, $cost`. Повторный запуск продолжает с места остановки: готовые ответы не пересчитываются. Звонки уходят модели только с `CQA_ALLOW_REAL_DATA=1`.

Сервер `make run` можно не останавливать: база работает в режиме WAL. Не нажимайте «Оценить» в интерфейсе одновременно со скриптом, иначе оба процесса оценят одни и те же пары.

Дополнительные параметры в `ARGS`: `--team` (название команды), `--model-name` и `--mode` (`external_api`, `local`, `hybrid`) — если поля `model` нужно указать вручную. Полный список — `scripts/results.py --help`.

## Формат JSON 1.0

Файл пишется в `results/<set>/results.json`:

```json
{
  "schema_version": "1.0",
  "team_name": "analysts",
  "model": {"mode": "external_api", "name": "qwen3-6"},
  "results": [
    {
      "conversation_id": "demo-001",
      "status": "ok",
      "criteria": [
        {"criterion_id": "contact", "value": true,
         "rationale": "Оператор поздоровался и представился в первом ответе.",
         "evidence_turns": [4]}
      ],
      "score": {"final_score": 77.69, "critical_flag": false}
    },
    {
      "conversation_id": "demo-002",
      "status": "error",
      "criteria": [],
      "score": null,
      "error": "нет оценки по критериям 04"
    }
  ]
}
```

| Поле | Откуда берётся |
| --- | --- |
| `results` | Одна запись на каждый `conversation_id` набора, в порядке источника |
| `criterion_id` | Код организаторов из `results/criteria_map.json`: соответствие кодов критериев — данные, а не код |
| `value` | «да» и «нет» — `true` и `false`, N/A — `null`, шкала — ступень, флаг — `true`, если найдено хотя бы одно нарушение |
| `rationale` | Обоснование модели; если ответ изменён решением — причина решения |
| `evidence_turns` | Номера реплик-оснований |
| `final_score` | Итог по формуле чек-листа с учётом последнего решения (см. [Чек-лист и расчёт итога](checklist)) |
| `critical_flag` | Найдена ли грубая ошибка |
| `model.mode` | `local`, если `CQA_DATA_WHERE=local`, иначе `external_api`; можно задать `--mode` |
| `model.name` | Модели из сохранённых ответов; второе мнение добавляется само, ручные ответы моделью не считаются |

Диалог, которого нет в базе или у которого нет допустимого ответа по какому-либо критерию карты, остаётся в файле со статусом `error` и причиной. Ошибка честнее нуля и пропуска.

## Проверка перед отправкой

Скрипт проверяет файл сразу после записи:

- нет повторов `conversation_id`;
- у каждой записи `ok` каждый код критерия встречается ровно один раз;
- `final_score` у записей `ok` — число;
- в `prod` ровно 10 записей, включая записи с ошибкой;
- `model.name` не пуст.

| Код выхода | Что значит |
| --- | --- |
| 0 | Файл записан, проверка пройдена |
| 1 | Файл записан, но проверка нашла проблемы: строки `FAIL` в выводе |
| 2 | Набор не загрузился или снимок набора не прочитан, файл не записан |

Строки `error <id>: <причина>` в выводе — диалоги, не оценённые по всем критериям. Если время есть, оцените их и повторите `make results`.

## После выгрузки

Файл публикуется коммитом в основную ветку репозитория команды: локальный файл без push организаторы не видят. Время, порядок шагов, запасные пути и действия при сбоях — в [регламенте](runbook).
