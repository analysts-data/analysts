# Встраивание в Dynamics 365

Интерфейс можно открыть внутри формы Dynamics 365 как HTML веб-ресурс решения. Сервер CQA работает отдельно, интерфейс обращается к нему по HTTP.

## Как устроен интерфейс

- Интерфейс написан на React (`frontend/`) и собирается командой `make web` в каталог `web/`. Собранный `web/` хранится в репозитории, поэтому для встраивания Node.js не нужен.
- Файлы для веб-ресурсов: `web/index.html`, `web/assets/index.js`, `web/assets/index.css`, `web/assets/Analytics.js`, `web/favicon.svg`. Имена без хешей и при пересборке не меняются. Внешних CDN и шрифтов из интернета нет, все пути относительные (`./assets/…`).
- Весь интерфейс находится в одном элементе `<cqa-app>`.
- Экраны переключаются по адресу после `#` (`#/queue`, `#/d/<id>`, `#/appeals`, `#/checklist`, `#/analytics`, `#/coaching`), поэтому форма Dynamics не перезагружается при переходах.
- Каталог `web/legacy/` — прежний интерфейс без сборки, для встраивания он не нужен.

## Шаги

1. Разверните сервер CQA на адресе, доступном пользователям Dynamics, по протоколу HTTPS (см. [Быстрый старт](quickstart)).
2. В решении Dynamics создайте веб-ресурсы для этих файлов с общим префиксом имени, сохраняя структуру каталогов: так относительные ссылки `./assets/index.js` и `./assets/index.css` продолжат работать.
3. Добавьте веб-ресурс `index.html` на форму или в карту сайта.
4. Передайте адрес API сервера в параметре `data`: Dynamics передаёт веб-ресурсу пользовательские параметры именно в нём. Значение — полный адрес API, например `https://<сервер>/api`.

## Как интерфейс находит сервер

Базовый адрес API выбирается в таком порядке:

1. Параметр `data` в адресе страницы: `index.html?data=https://<сервер>/api`.
2. Атрибут `data-api` элемента `<cqa-app>` в `index.html` (по умолчанию `/api`).
3. Если не задано ни то, ни другое, — `/api` того же сервера.

Без параметра `data` интерфейс работает так же, как при открытии с самого сервера CQA.

## Кросс-доменные запросы (CORS)

Сервер разрешает кросс-доменные запросы только с доменов Dynamics:

| Параметр | Значение |
| --- | --- |
| Источник | `https://` и любой поддомен `*.dynamics.com` (регулярное выражение в `src/cqa/http/app.py`) |
| Методы | `GET`, `POST`, `PUT` |
| Заголовки | `Content-Type` |
| Cookies и учётные данные | не передаются |

Запросы с других доменов браузер отклоняет. Из Dynamics доступны чтение состояния, загрузка наборов, запуск оценки, ручные ответы, апелляции, решения и правка чек-листа. Удаление провайдера модели (`DELETE`) из встроенного интерфейса недоступно: это делается в интерфейсе, открытом с самого сервера.

## Записи звонков

Плеер в карточке звонка обращается к `GET /api/dialogs/{id}/audio`. Сервер каждый раз запрашивает свежую подписанную ссылку на запись и перенаправляет на неё; ссылка не хранится в браузере и не попадает в ответы API. Для воспроизведения в Dynamics дополнительных настроек CORS не нужно.

## Ограничения

- Учётных записей нет: роль переключается кнопкой в шапке интерфейса. Доступ к серверу ограничивайте сетью (см. [Безопасность и данные](security)).
- Кросс-доменные запросы идут без cookies, поэтому вход по токену (`CQA_ACCESS_TOKEN`, `make share`) встроенный интерфейс не проходит: сервер для Dynamics запускайте без токена, в закрытой сети.
- Сервер проверяет только источник запроса браузера. Запросы не из браузера, например интеграция по API, CORS не ограничивает (см. [Интеграция по API](integration)).
