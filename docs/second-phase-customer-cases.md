# Phase 2: Repeat contacts and case solutions

## Bank source fields

Each imported conversation may include:

```json
{
  "conversation_id": "conversation-123",
  "client_ref": "v1:opaque-pseudonym",
  "case_status": "open",
  "channel": "Voice Call",
  "language": "Russian",
  "transcript": [
    { "timestamp": "2026-11-08T10:15:00+05:00", "speaker": "client", "text": "..." }
  ]
}
```

- `client_ref` must be a stable pseudonymous value generated by the bank integration. Never use a name or phone number as the key. Keep any re-identification map inside the bank environment.
- `case_status` is optional and accepts `unknown`, `open`, `in_progress`, or `resolved`. The customer-cases screen can also update one dialogue's status.
- Records without `client_ref` continue to be ingested, but are not linked to a customer case.

## Approved offer catalogue

The existing `/api/products` catalogue is for classifying conversation topics. It is not a bank offer catalogue.

QA can maintain approved offers in **Каталог решений**. An offer has:

- `id`, `name`, `description`
- `topic_ids`: existing conversation topic IDs that the bank has approved as a match
- `keywords`: exact phrases to search in client utterances (add Russian, Kazakh and English forms as needed)
- `next_step`: suggested employee action
- `eligibility`: conditions to verify before making the offer
- `approved`: only approved offers can be suggested

The API is `GET/PUT /api/customer-offers`. A topic ID must already exist in `GET /api/products`.

## Matching and resolution behavior

- Conversations are grouped only by `client_ref`.
- A suggestion appears only for an approved offer that matches a configured topic ID or a configured phrase in a client-authored transcript turn from a dialogue marked `open` or `in_progress`. Resolved or unknown cases do not trigger an offer suggestion.
- Phrase matching uses case-insensitive substring matching. It does not infer synonyms or paraphrase the client's request; configure likely forms explicitly.
- The suggestion includes its match reason and available transcript evidence. Employees must check the client's situation and offer eligibility.
- If no approved offer matches, the dashboard says there is no grounded suggestion.
- Dialogue resolution can be set with `PUT /api/dialogs/{dialog_id}/case-status` and body `{"status":"resolved"}`. The status is stored with the dialogue and affects unresolved counts and case priority.
- Priority is a transparent review aid based on repeat contacts, repeated themes, unresolved statuses, and risk markers. It is not a churn prediction.

This is a prototype integration contract. Confirm the bank's authoritative case-status source, offer catalogue, eligibility rules, and access controls before connecting production data.
